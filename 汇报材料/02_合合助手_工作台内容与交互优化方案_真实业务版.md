# 合合助手工作台：真实业务内容与交互优化方案

**版本：V6／与真实调研场景方案配套**  
**编制日期：2026年9月13日**  
**对象：本轮上传的“合合助手”工作台设计截图。**  
**目标：保留数智北京创新中心品牌与现有蓝白视觉，将通用AI工作台改为面向中心真实创新业务的服务入口；本轮提供文案和交互规格，不修改官网、不提交业务。**

> 本文涉及的业务事实，依据两份客户QA、官网公开表单、HHagent原站镜像和2026年9月2日数据快照。所有新增导航、UI状态、草稿机制和工具接口均为设计建议，不能据此宣称已上线。详细事实、访问限制及28题映射见配套场景方案第1—4节。

## 1. 对当前设计稿的判断

当前稿已建立合合吉祥物、蓝白波纹背景、四色卡片和官网品牌联系，可以沿用。主要问题不在于颜色，而在于**内容泛化、首屏操作滞后、真实业务边界不清、入口重复**。

| 位置 | 当前内容／观察 | 为什么需要调整 | 优化方向 |
|---|---|---|---|
| 顶部官网栏 | 官方Logo、9个导航和登录入口 | 是原门户，不属于本次助手重构范围 | 保持原样，不重新生成文字、链接、选中项或登录状态 |
| 中央欢迎区 | 大吉祥物、大问候、背景占据大半屏 | 输入框被推至图片接近底部；用户先看宣传再找操作 | 吉祥物收至欢迎区辅助位置，输入框移到欢迎语后，首屏可直接提问 |
| 左侧“数据空间” | 容易被理解为可进入数据开发环境 | F2说明可信数据空间/政务外网有条件，不是互联网通用工作区 | 移出公共左栏；用“数据创新指引”解释路径，不提供无依据直达 |
| 左侧“应用广场” | 泛化的AI应用市场 | 容易与官网“创新成果/应用超市”和助手技能混淆 | 改“服务导航”，按真实业务入口组织；不把Skills当用户要研究的功能市场 |
| 中央模式 | 问答、问数、边聊边办 | 可保留识别性，但不应割裂成三套会话 | 作为能力入口和示例切换，任务可自动衔接，手动切换不丢草稿 |
| 橙色卡片 | 咨询创新服务 | 范围太泛，与欢迎语/常见问题重复 | 改为“参与场景揭榜”，立即明确一个真实任务方向 |
| 绿色卡片 | 查询数据资源目录 | 方向正确，副文案“可用资源”可能暗示使用权 | 改“查找数据资源”，说明查询目录及获取条件 |
| 红色卡片 | 查看政策解读 | 不足以突出中心核心服务 | 改“数据创新项目”，以项目申请准备代替泛化政策入口 |
| 蓝色卡片 | 发起数据申请 | 容易承诺在互联网直接提交公共数据申请 | 改“预约参观”；需求反馈放在常用服务和资源结果中显著承接 |
| 右侧“热门推荐” | 泛AI服务、最新政策、生成北京经济报告 | 没有真实热度证据；报告生成偏离首批中心任务 | 改“常见问题”，直接采用28题中的真实问题 |
| 右侧“我的常用” | 政策法规库、申请记录、收藏等 | “我的”没有账户状态；“政策法规库”不是已核实的独立官网事项 | 访客显示“常用服务”；登录后显示“继续办理”，数据来自授权接口 |
| 底部多个横幅 | 左下吉祥物、右下城市宣传、重复口号 | 同一页重复品牌曝光，挤占有效空间 | 保留一处简洁品牌表达，其余移除或仅在欢迎页极弱展示 |
| 输入区 | “/选择技能”、深度思考、联网搜索 | 把Harness内部能力和知识来源选择转嫁给用户 | 直接表达任务；高级设置收起，默认中心核定资料和授权资源 |

**核心改动不是把每张卡片写得更长，而是让每个入口能够回答：我会进入什么业务、下一步做什么、现在能做到哪一步。**

## 2. 产品定位和信息架构

### 2.1 新定位文案

**主标题：** 您好，我是合合  
**副标题：** 帮您了解创新服务、查找资源、准备申请。  
**输入框提示：** 说说您想了解什么，或准备办理什么事项……

“合合助手 Beta”保留在工作台标题，不再在欢迎、侧栏、输入区和每个卡片重复展示。正式业务环境是否保留Beta由上线管理决定；原型环境用独立、清晰的“原型演示”标识，不以Beta代替演示说明。

不使用“帮您办理所有相关业务”“一问即办结”“全市资源任意调用”等越界文案。首页不展示对模型性能的营销口号。

### 2.2 左栏：从工具菜单改为用户任务导航

建议常驻五项：

| 新导航 | 内容和行为 | 没有相应能力时如何处理 |
|---|---|---|
| 新建对话 | 新建咨询会话；已保存任务不删除 | 有未保存草稿时提示保存或放弃，不能直接清空 |
| 最近会话 | 按主题与时间恢复咨询；敏感内容摘要化 | 只有浏览器内存能力时标“本次会话”，不能宣称云端历史已同步 |
| 我的办理 | 分“助手草稿”“正式业务记录”；继续已有任务 | 访客先登录；业务记录接口未接通时仅显示草稿和去个人中心指引 |
| 资源收藏 | 收藏目录、场景、成果和服务入口；保留来源与版本 | 未接收藏接口时标本地/演示收藏，不能伪装官网已收藏 |
| 服务导航 | 按真实业务分类的入口清单 | 未核实/当前不开放的入口不显示“立即办理” |

底部保留“帮助与反馈”；“设置”收进账号菜单。删除左下重复吉祥物横幅。治理后台通过独立授权入口进入，不把知识编辑、图谱维护、Harness运行控制放入普通用户左栏。

### 2.3 服务导航的业务目录

| 分组 | 建议显示的真实入口 | 行为约束 |
|---|---|---|
| 参与场景创新 | 场景目录、场景申请、我的申报进度 | 先选已发布场景；检查批次、身份及当前可操作状态 |
| 开展数据创新 | 数据创新项目、项目/团队指引、资源获取指引 | 公共数据申请使用区分互联网与政务外网，不直接跨网 |
| 查找创新资源 | 数据目录、云网算力目录、组件目录、技术创新能力、创新成果 | 资源可见/开放/共享/可申请分别说明 |
| 提供资源与能力 | 提供数据、提供组件、提供场景、提供应用、提供服务 | 沿用“我要提供”真实Tab；提交不等于上架或官方发布 |
| 到访与服务对接 | 参观预约、需求反馈、入驻指南、加入伙伴 | 入驻意向按说明转反馈；伙伴类别和申请期分别核对 |
| 了解评测服务 | 大模型测评、感知算法测评、技术能力验证 | 以服务说明与咨询为主；原镜像灰色按钮不包装成已上线的申请页 |

这里是助手导航分类，不改写官网自身一级栏目。别名检索应支持“场景创新/场景培育”“数智创新成果/数据创新”等历史用语，但最终链接显示当前核对的页面名称。

## 3. 首页可直接替换的全部文案

### 3.1 三种能力入口

| 标题 | 副文案 | 点击后的作用 |
|---|---|---|
| 问答 | 服务说明 · 条件核对 | 切换为业务咨询示例，仍可直接输入所有问题 |
| 问数 | 目录查询 · 资源比较 | 切换为可核验目录查询示例，不打开万能数据分析面板 |
| 边聊边办 | 申请准备 · 办理接续 | 展示真实事项与已有任务；新建草稿前核对事项，不自动提交 |

首次打开可默认问答示例，但后台根据真实意图选择工具；切换模式不创建新会话、不清空资料，也不能把对办理条件的提问自动解释成确认提交。

### 3.2 四张主卡片：保留四色视觉，替换为真实任务

| 原卡片色系 | 新标题 | 两行说明 | 主动作与去向 |
|---|---|---|---|
| 橙黄 | 参与场景揭榜 | 查找已发布场景，<br>了解申报条件与材料。 | “了解如何参与”→S02/S04；选定场景后才进入S07 |
| 青绿 | 查找数据资源 | 查询资源目录，<br>核对获取方式与使用条件。 | “查找资源”→S03；非开放目标衔接需求反馈 |
| 主题红 | 数据创新项目 | 梳理项目申请与<br>入场准备的办理路径。 | “准备项目申请”→S08；明确是创建准备，原表需登录 |
| 蓝色 | 预约参观 | 选择个人或团体预约，<br>按页面要求准备信息。 | “开始预约”→S06；不展示虚构可约名额 |

“需求反馈”并非不重要：它位于右侧常用服务第一位，也在无结果、无法直接获取、入驻咨询和用户明确需求时出现，作为跨场景承接入口。供给方可从服务导航进入“提供组件/场景”等；登录后可根据用户显式选择的任务替换一张快捷卡，但不偷偷推断角色。

避免卡片含多种同权重按钮。卡片标题、说明和箭头共用同一个动作，键盘和鼠标均可触达。

### 3.3 右侧“常见问题”：采用真实客户问题，不使用无依据热度

默认显示五条，文字可直接使用：

1. 申请资源时没有项目名称是什么原因？（F2问题7，S01）
2. 如何进行创新场景的申报？（F2问题1，S02→S07）
3. 能否以联合体形式进行场景揭榜？（F1问题4，S02）
4. 如何申请公共数据进行数据创新？（F2问题5，S08）
5. 如何确认场景申报已成功？（F2问题2，办理记录指引）

“查看全部”打开按原两份清单分类的帮助列表。“换一换”在审核通过的问题库中轮换，不随机生成政策问题，不按未经统计的数据标“热门”。

A11路演时限、A17采购关系等待审核问题不作为首页示例；用户主动问到时提供已审核内容或核实路径，不能回避处理，更不能给未核实承诺。

### 3.4 右侧第二块：根据真实状态显示

| 用户/系统状态 | 标题 | 内容 |
|---|---|---|
| 未登录 | 常用服务 | 需求反馈、入驻指南、加入伙伴、提供资源与能力；每项按真实入口分流 |
| 已登录，无任务 | 开始一项任务 | 查找场景、准备数据创新项目、预约参观；不伪造“您有3项待办” |
| 已登录，有助手草稿 | 继续准备 | 显示草稿事项、更新时间、缺项、继续按钮；标“助手草稿，未提交官网” |
| 已登录，业务接口已接通 | 我的办理 | 真实事项、业务编号、返回状态、查询时间及当前允许操作 |
| 业务查询失败 | 暂未取得办理记录 | 重试、前往个人中心；不显示“暂无申请”冒充空结果 |
| 仅原型演示 | 演示任务 | 状态和编号明确标演示；任何账户名/单位名用虚构标识 |

不在欢迎页常驻长审批时间轴；有明确任务后，进度卡按需打开。

### 3.5 输入区与示例问题

输入框置于欢迎语之后、快捷卡片之前。访客无需先选模型、知识库或Skill即可提问。

**问答示例：**“我们想参与场景创新，应该从哪里开始？”“资源申请看不到项目名称，怎么处理？”  
**问数示例：**“交通运输领域有哪些政府侧数据目录？”“按目录阶段统计场景数量，再看我关注的批次。”  
**办理示例：**“帮我准备一份需求反馈。”“我们单位想预约参观创新中心。”

这些问数和办理表述是基于真实业务推导的设计话术，不标为客户逐字原话。默认一次只显示2—3条，和右侧问题避免完全重复。

输入底部建议保留附件、发送及必要的资料范围提示；不默认展示“/选择技能”。高级用户的快捷命令可后置，但不能作为普通用户的主路径。

| 当前控件 | 建议 | 具体交互 |
|---|---|---|
| 深度思考 | 从首页主操作中移除 | 执行策略由Harness按任务复杂度选择；用户可选“更详细地说明”，不必理解推理档位 |
| 联网搜索 | 不默认启用任意全网 | 先使用中心核定资料与授权目录；需外部依据时展示来源范围及访问结果，不伪造检索 |
| 附件 | 保留，但目的明确 | 选择“辅助理解/整理材料”；上传到助手、解析、写入正式表单是不同操作 |
| 发送 | 保留小尺寸低干扰主按钮 | 空输入或只含未就绪文件时禁用；发送后可停止生成，但不能将停止解释为撤销已提交业务 |
| 语音 | 暂不展示未实现的麦克风 | 若后续有可用服务及授权再开放，原型不暗示可用 |

页脚改为：“**答复附来源；正式办理结果以业务系统为准。**”原型环境额外显示“**当前为原型演示，未向官网提交业务。**”免责声明不能替代字段校验和事实核对。

## 4. 布局与尺寸：不让宣传内容压过操作

### 4.1 1440×900桌面设计基准（均为建议尺寸）

官网顶部区域沿用原站实际高度，不能为了助手缩放Logo、改导航文字或挪动登录入口。助手工作台使用剩余可视高度，内部各区独立滚动，不挤压官网。

建议布局：左导航约176px，右辅助栏约256px，栏间距16px，中间自适应。欢迎区高度控制约160—190px；吉祥物可视高度约140—170px，最多出现一次。输入区高度约108—140px；卡片高度约120—140px；底部不再新增城市宣传图。

```text
原官网顶部导航（保持）
┌──────────┬─────────────────────────────┬────────────────┐
│ 合合助手 │ 紧凑欢迎语＋小吉祥物          │ 常见问题        │
│ 新建对话 │ 输入区／附件／发送             │ 5条真实问题     │
│ 最近会话 │ 问答 · 问数 · 边聊边办         │                │
│ 我的办理 │ 4张真实业务快捷卡片            │ 常用服务        │
│ 资源收藏 │ 当前任务／最近使用（有数据才显示）│ 或继续办理      │
│ 服务导航 │                             │                │
│ 帮助反馈 │                             │                │
└──────────┴─────────────────────────────┴────────────────┘
```

标题、输入框、至少三种示例和四个快捷入口在1440×900首屏可见；不能以缩小正文到难以阅读来换取“全部显示”。对长标题，换行或截断并提供完整查看，不用极细灰字隐藏关键条件。

### 4.2 视觉保留与微调

沿用截图的官网品牌、黄色合合、蓝白背景及黄/青/红/蓝四色。助手主交互蓝不改变官网导航红。四色卡片用低饱和浅底、细边框、轻微角落渐变；不增加粗顶边或大阴影。

建议助手文字层级：页标题24—28px、卡片标题16—18px、正文14—16px、来源辅助信息12—13px。模式选中态以浅蓝填充＋明确文字/底线表现，减少当前大块高饱和胶囊的视觉抢占。发送按钮用紧凑蓝底或浅蓝底深蓝图标；与主体卡片争夺注意力的强渐变减少。

Beta缩为小标签，图标服务于识别，不在每条助手消息重复大头像。实际可读性需在标准浏览器和最终截图中验证，本方案不声称已经完成无障碍认证。

### 4.3 进入对话后

大欢迎区和四色卡片收起，保留紧凑会话标题。回答先给能执行的结论；依据默认一行入口，展开后可定位原文。一次回答最多一个主行动，其他解释为次级链接。侧栏助手可以先保留窄形态；涉及多列目录、表单或材料对照时才展开工作区。

咨询中不常驻办理长表单；用户选择具体事项或主动打开核对时再呈现。右侧常见问题和推荐栏在任务状态关闭，不与聊天和表单争空间。

## 5. 办理工作区：左侧业务页面、右侧合合，比例2:1

### 5.1 不再将左侧又拆成“表单＋重复摘要”两份同样内容

原先生成的办理图左侧同时展示表单和完整AI摘要，信息重复，且页面头部、步骤条过大。本次采用：**左侧真实业务表单；右侧对话；底部一条简短的同步/核对状态。**完整摘要只在提交前核对页展示一次。

1440px宽画布示例：两侧边距各16px，左右间距16px，净列宽1392px，左928px、右464px，严格2:1。实际官网嵌入时按容器宽度计算，不固定让右侧覆盖原表字段。

```text
原官网导航（保持）
┌───────────────────────────────────┐ ┌──────────────────┐
│ 需求反馈  [草稿·未提交]             │ │ 合合助手 Beta ⋯  │  ← 48—56px
│ 企业名称   联系人                  │ ├──────────────────┤
│ 联系电话                           │ │ 简短连续对话      │
│ 需求详情（刚修改部分高亮）           │ │ 已填写/待确认反馈 │
│                                   │ │ 必要追问          │
│ 来源对象：轨道交通进出站客流信息     │ │                  │
│ 本次修改：算力服务→GPU卡算力服务    │ │ 输入区/发送       │
│ [保存草稿]        [核对信息]         │ │                  │
```

“来源对象”是助手附加上下文区，不冒充需求反馈原表必填字段。左侧可读字段必须与右侧说过或用户在表单填写的内容对应；AI建议自动补写的字段须标“建议内容，待确认”。

### 5.2 事项标题必须使用真实名称

| 场景 | 正确标题 | 不应使用的标题/含义 |
|---|---|---|
| 非开放数据、入驻或服务诉求 | 需求反馈 | 公共数据审批申请（未核实的互联网表） |
| 已发布场景揭榜 | 场景申请＋真实场景全名 | 城市交通新场景发布（把需求方和揭榜方混淆） |
| 企业提供业务场景 | 提供场景 | 场景揭榜申请 |
| 自主数据创新项目 | 数据创新项目／创建准备 | 直接获取公共数据 |
| 提供工具能力 | 提供组件／共创伙伴申请·组件类 | 组件采购审批 |
| 参观 | 数智北京创新中心参观预约 | 入驻审批 |
| 申请加入评测合作生态 | 政务大模型评测区合作伙伴申请 | 大模型检测服务申请 |

标题后面的“草稿、待补充、待核对”等为助手任务状态，与官网返回的正式状态分开。

### 5.3 右侧对话顶部与内容

顶部48—56px：24—28px品牌图标/小头像、标题16—18px、Beta小标签、更多、收起。不再放“有问题找合合”第二行口号和大横幅；事项名称由左侧标题表达，右侧可在会话顶部放一行“当前任务：需求反馈”。

对话区域至少占右栏剩余高度的70%左右（实际随输入区及来源提示调整）。气泡宽度不超过右栏可用宽度的约88%；用户在右、助手在左。最多展示近期必要轮次，历史仍可上滚，不为了截图堆满8条长回答。

需要说明过程时使用“正在核对目录”“已更新需求详情”“还需补充联系电话”等真实事件；不展示随机百分比、原始思维链或“已思考34秒”来代替业务进度。

### 5.4 同步反馈与冲突处理

| 事件 | 左侧 | 右侧 |
|---|---|---|
| 用户在对话明确提供信息 | 更新相应字段，短时浅色高亮 | “已填写企业名称和需求详情，还需联系人及电话。” |
| AI从附件提取候选 | 显示候选/来源，不直接覆盖已确认值 | “发现一处版本信息，请核对后采用。” |
| 用户手动改字段 | 更新当前草稿修订；撤销旧候选 | 不反复弹通知，可简短显示“已与表单同步” |
| 旧轮次异步结果回来 | 若版本已变化，不覆盖新值 | 提供差异或忽略旧结果；不重复追问已填字段 |
| 用户说“其他不变” | 仅patch目标字段 | 说明改了哪项，禁止重新生成整张表 |
| 当前字段不满足规则 | 保留原输入，字段下解释错误 | 问清真实意图，确认后再转换；尤其金额/单位不猜测 |
| 用户退出办理 | 按权限与保存能力保留草稿/提示 | “继续咨询”不丢草稿；清空对话不等于删除官网业务 |
| 事项切换 | 要求确认创建另一草稿，保留原任务 | 明确新事项名称，不把查询文本写入旧申请 |

### 5.5 提交前核对与提交结果

“核对信息”→只读摘要→用户明确“确认提交”。核对页显示真实事项、目标对象、将提交的内容、材料状态和去向；不能靠一句“好的”完成全部授权。

提交中禁用重复按钮；停止模型生成不打断已发出的业务请求。结果不明时显示“尚未确认是否提交成功”，先查询同一请求或指引人工核实。**没有回执字段就不造回执号；没有状态接口就不显示假的实时进度。**

模拟按钮统一“确认提交（演示）”，结果“模拟业务反馈”。实体数据的名称可用真实目录，业务提交状态不得假扮真实。材料仅被助手读取时写“已用于整理”，正式上传成功需独立接口结果。

## 6. 不同模式下应该展示哪些真实内容

### 6.1 问答：从普通答案升级为有对象、有条件的解释

| 问题 | 回答主体 | 可展开内容 | 一个合适的主行动 |
|---|---|---|---|
| 申请资源没有项目名称 | 先解释团队管理员要求，再核对角色/项目/网络 | 权限来源或自查步骤 | 核对办理条件 |
| 联合体能否揭榜 | 先明确场景/批次，再解释牵头和成员准备 | 本批次通知、原始指南 | 选择要参与的场景 |
| 公共数据如何用于创新 | 互联网准备与线下政务外网使用分开 | 项目、团队、入场、数据申请路径 | 查看数据创新项目指引 |
| 申报保存失败 | 明确当前事项和错误，不猜测后台异常 | 出错字段、数据类型、用户确认转换 | 返回对应字段修改 |
| 认证失败 | 区分统一身份认证和业务系统权限 | 官方帮助，不显示敏感凭证 | 打开认证帮助 |

来源卡保留标题、来源类型、适用对象和版本。不能在答复后随意挂一个法规链接就标“权威依据”。待核实的A11/A17等不渲染为已确认结论。

### 6.2 问数：从“分析一切”收敛为有数据基础的查询

问数页面固定显示：**数据对象、有效筛选条件、数据时间、统计口径、权限范围**。工具计算结果、图表与明细同源。

首批两种图表足够：交通目录提供部门横向条形图；场景目录阶段分布。后者标题必须“目录阶段分布（快照）”，不能改成“当前可申请场景”。

第一屏显示关键结果和不超过5条明细，完整列表按需展开。过滤条件变化独立可见；点击图表和自然语言追问应操作同一份过滤状态。资源比较只对照已知字段，暂无数据则显示“未提供”，不用星级或98%等未评测分值。

具体口径固定为：目录614→交通委569→开放38；交通委全部领域583；场景目录阶段49/37/105。2026-09-02快照与实时数据不得混排。F3样例仅628条覆盖子集，超范围问题提示“当前演示数据不覆盖该范围”，不展示0条。

### 6.3 边聊边办：不是把所有流程画成同一种四步表单

- **需求反馈**只有四个真实必填字段，默认单页即可；无需“基本信息/场景描述/资源需求/核对提交”的庞大步骤条。
- **参观预约**按个人/团体字段切换，日历与人数变化可能改变处理路径，不能套项目字段。
- **提供组件**字段较多，按工具信息、材料、单位资料分组；可以折叠，但缺项摘要仍可见。
- **场景申请**必须绑定已发布场景；真实表单未取得前，只展示准备页及原入口。
- **数据创新项目**与团队/入场是阶段化服务；不给所有普通用户同时显示一排可点的资源申请按钮。

## 9. 设计验收与交付清单

**内容验收**：无“发起数据申请即可取得公共数据”、无泛化“政策法规库”、无无依据的热门排行；参与场景与提供场景分开；提供组件与获取组件分开；伙伴招募与申请测评分开。卡片、FAQ、资料与原办理页名称对应。

**布局验收**：1440×900首屏输入可见；欢迎吉祥物不超过主体操作；进入任务后隐藏右侧推荐与大欢迎区；办理净宽2:1；助手标题48—56px；没有左右双份完整重复摘要。

**交互验收**：一句话修改一个字段；手动修改不被旧响应覆盖；缺项阻断；明确核对和提交；原型与正式状态分开；返回咨询后任务仍可接续；无来源不生成准入结论。

**数据验收**：统计与明细同源、快照标识清楚、原始属性保真；缓存日历不作为实时余量；目录阶段不等于当前受理窗口；本人记录通过授权接口读取。

**工程验收**：前台模式不是三套孤立会话；复杂任务可由Harness调度工具，简单查询直达；写操作受控；不展示未实现的语音、跨网数据、任意电脑控制等入口。

**最终素材**：每张主图只表达一个核心交互；标题、来源和演示标识可读；优先从可运行原型截图。图像生成仅用于视觉探索，不能决定真实字段、数字和业务状态。
