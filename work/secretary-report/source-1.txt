一、网站当前内容分析
从网站现有栏目和服务能力出发，梳理各业务板块与合合助手可承接的智能服务类型。
二、网站有哪些数字资源
平台数字资源覆盖多个领域和部门，既需要传统检索，也需要面向目录的精确统计与结构化问数能力。
用户问“某部门有哪些数据集”时，调用目录数据库进行完整统计和分页查询。
三、网站有哪些办理事项
平台已经存在一系列可查询、可申请、可审批、可跟踪的业务事项，这些事项构成“边聊边办”和进度跟踪的主要接入对象。

用户故事

• 可以申请入驻、工位或相关创新服务。
最终结果
用户不需要自己研究网站栏目，合合直接生成一张“企业创新服务路线图”，并提供：
完善企业认证 → 创建或关联项目 → 查看推荐资源 → 加入资源方案 → 发起申请。

7. 对话式业务办理，也就是“边聊边办”
这是合合最有辨识度的服务。
用户不需要自己找入口、打开表单、反复填写，而是通过聊天完成：
需求识别 → 前置条件检查 → 信息补全 → 确认提交 → 获取回执。
建设方案明确提出，边聊边办应接入需求登记、数据资源申请、算力申请、揭榜申请、机构入驻和要素服务等事项，并支持信息采集、校验、确认、提交和回执。

合合提供的服务

主动推送：
“您的算力申请待补充项目预算明细，建议今天 18:00 前完成。”
用户点击后，合合直接打开对应办理会话，说明：
• 为什么需要补充；
• 支持什么文件格式；
• 已有材料有哪些；
• 缺少哪一项。
最终结果
用户上传材料后，合合调用补正接口并反馈提交结果。
例子三：项目进度和验收提醒
用户故事
某场景创新项目即将进入验收阶段，但还未上报最新开发进度。
合合提供的服务
合合提醒项目负责人：
• 当前项目阶段；
• 需要上报的进度材料；
• 验收申请时间；
• 应上传的附件；
• 若被要求限期整改，整改截止时间。
• 现有流程已经包含开发过程上报、验收申请、通过、不通过和限期整改等节点。
最终结果
合合不仅告诉用户“有一个待办”，还直接带用户完成该待办。
9. 数据创新、可信空间开发与成果转化服务
这是平台区别于普通数据开放门户的重要能力。
这类服务覆盖：
项目申请 → 资源申请 → 可信空间开发 → 过程管理 → 开发验证 → 产品上架 → 质量测试 → 专家评审 → 成果推广。
现有手册明确说明，创新开发者可以在政务外网可信数据空间沙箱中使用公共数据进行开发。
例子一：进入可信数据空间开展开发
用户故事
数据创新项目已经立项，团队准备开始使用公共数据。
合合提供的服务
合合检查：
• 项目是否审核通过；
• 团队是否创建；
• 场地和人员是否审批；
• 是否已经开通政务外网；
• 是否具备动态码登录条件；
• 资源是否审批通过。
• 现有流程规定，政务外网环境需要使用京通小程序动态码登录工作空间。
最终结果
用户得到“可以进入可信空间”或“还缺哪些前置条件”的明确结论。
例子二：开发过程和验证管理
用户故事
开发团队已经完成第一版模型，需要提交阶段成果。
合合提供的服务
合合根据项目节点提示：
• 本阶段应提交什么材料；
• 需要选择哪个进度节点；
• 已提交材料是否完整；
• 是否可以进入下一阶段；
• 是否需要继续在可信空间开发。
最终结果
用户说“帮我上报本周进展”，合合将对话内容整理成结构化进度记录，并在确认后提交。
例子三：产品上架、质量测试和专家评审
用户故事
企业已经形成一个基于公共数据开发的数据产品，希望上架并推广。
合合提供的服务
合合引导用户完成：
• 产品上架申请；
• 用途和应用场景说明；
• 数据需求和使用期限说明；
• 第三方质量测试；
• 专家评审材料准备；
• 评审结果查询；
• 后续成果推广申请。
产品上架需要明确实施单位、用途、应用场景、数据需求、数据类型、使用期限和主要服务对象；之后还需第三方质量测试和专家评审。
最终结果
合合成为项目从“数据申请”走到“成果转化”的全生命周期助手。
10. 专家咨询与人工协同服务
这类服务解决的是：
“问题太复杂，AI 不应该自己下结论。”
“涉及跨部门、合规或特殊事项，需要人工判断。”
“系统异常时，不能让用户自己从头解释一遍。”
现有方案明确要求，在接口失败、网络超时、系统繁忙等情况下，提供转人工、线下办理、再次提交或补充材料等兜底方式。
这里需要说明：附件支持“转人工兜底”的方向，但专家排队、预约时段和专家画像等详细功能，是本轮产品原型进一步扩展的设计。
例子一：复杂跨部门数据申请
用户故事
企业需要申请高精度三维城市模型数据，用于城市更新项目，涉及多部门审批和安全合规。
合合提供的服务
合合先整理：
• 用户核心诉求；
• 数据用途；
• 项目情况；
• 可能涉及的部门；
• 现有附件；
• 需要进一步确认的问题。
• 然后生成“人工接力卡”，转给数据资源专家。
最终结果
专家接手时不需要让用户重新讲一遍，已有对话、材料和初步判断全部随工单传递。
例子二：政策适用边界不明确
用户故事
企业询问：
“我们的数据产品既服务政府，也面向商业客户，这种情况是否允许？”
合合提供的服务
合合先提供已有政策依据，但识别到该问题涉及具体数据类别、使用协议和商业用途边界，无法仅靠通用知识安全作出结论。
最终结果
合合明确说明“需要人工合规判断”，并预约政策或数据合规专家，而不是生成一个看似确定、实际可能错误的答案。
例子三：办理接口异常
用户故事
用户已经填写完算力申请，但提交时业务系统超时。
合合提供的服务
合合不会让用户重新填写，而是：
• 保存办理草稿；
• 保留已填写字段；
• 返回异常原因；
• 生成故障编号；
• 提供再次提交；
• 联系人工；
• 稍后自动提醒继续办理。
最终结果
用户的业务不因后台短时故障而中断。

医学影像数据 + GPU 算力 + 图像预处理组件 + 合规评估 + 模型测试服务。
第五步：匹配场景
合合发现平台上有“医疗影像辅助诊断”类场景需求，并给出企业与该场景的匹配分析。
第六步：边聊边办
